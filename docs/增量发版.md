# 发布下一个 Windows 便携版

给 AI 的指令：**按 docs/增量发版.md 把当前变更发布为 X.Y.Z。用上一个正式包制作签名补丁，验收软件内下载、重启与资料保留，再推送源码、发布 GitHub Release，验证国内加速和直连的清单、补丁与完整包。不要操作我正在使用的客户端。**

## 先确定基线与发布身份

源码和发布附件都在 **AsaMisogi/Cloudmusic-Lyrics-Singing**；正式分支为 main。用 git status、git remote -v 和 gh release view 确认当前仓库及最新正式标签。使用已登录的 Git 和 GitHub CLI（本机为 .tools/gh/bin/gh.exe）；不提取 Token，不向代理发送登录请求。国内加速是公开 GitHub 附件的读取入口，不是另一个可上传的仓库；本项目无需香港服务器。

基线必须是用户实际收到的上一个正式 **Utatomo-X.Y.Z-windows-x64.zip**，不能拿临时构建替代。同一版曾重发：0.8.3 的正式基线在 dist/0.8.3-sidebar/，不是 dist/0.8.3-release/。从 Release 下载或复用本地包，比较 Get-FileHash 的 SHA256 与 GitHub 附件 digest，再开始制作。

签名公钥在 assets/update-signer.cer。配套私钥在发布机当前用户的 Windows「个人」证书库，名称 **Utatomo Update Signing v1**。请所有者通过 certmgr.msc 导出带密码的 PFX，离线保管。换发布机时由所有者导入原私钥；找不到匹配密钥就停止签名，不新建证书替代。无需私钥即可从源码运行、构建普通便携包和验签。

## 构建与验收

1. 在独立输出目录构建，不覆盖正在运行的目录。同步 utatomo/__init__.py、pyproject.toml、uv.lock 的项目版本，更新 README 与 docs/release-X.Y.Z.md。不要把上版的版本号写死在「发现新版」测试夹具中。
2. 以下以首次 0.8.3 → 0.9.0 为例，在项目根目录 PowerShell 执行。以后换成实际路径与版本：

~~~powershell
$py = '.venv/Scripts/python.exe'
$v = '0.9.0'
$dir = "dist/$v"
$base = 'dist/0.8.3-sidebar/Utatomo-0.8.3-windows-x64.zip'
$full = "$dir/Utatomo-$v-windows-x64.zip"
& $py -m unittest discover -s tests
& $py scripts/build_release.py --dist-dir $dir
& $py scripts/make_update.py $base $full
& $py scripts/qa_portable_update.py $base $dir
~~~

QA 解压一份隔离旧版，用真实设置、下载与重启按钮、签名发布附件和独立助手，检查新版窗口的就绪回执与个人数据。下载用本地附件替代公网；发布后再验证两条真实线路。用构建好的 Utatomo.exe --smoke-test --headless 检查包内播放器，退出码应为 0。每一步失败先修复，不公开未通过的包。QA 截图和隔离安装在 build/update-qa-*。

## 只上传一次，验证两条线路

确认 diff 与暂存内容；不要提交用户 data、构建目录、PFX 或凭据。提交并推送 main。用当前提交开草稿，将下列三件套传齐，再设为最新正式版：

~~~powershell
$gh = '.tools/gh/bin/gh.exe'
$repo = 'AsaMisogi/Cloudmusic-Lyrics-Singing'
$patch = (Get-Item "$dir/Utatomo-*-to-$v-patch.zip").FullName
& $gh release create "v$v" --repo $repo --target (git rev-parse HEAD) --draft --title "咏伴 $v" --notes-file "docs/release-$v.md"
& $gh release upload "v$v" $full $patch "$dir/update.json" --repo $repo
& $gh release view "v$v" --repo $repo --json assets,isDraft
~~~

核对附件名称、大小和 GitHub 的 digest 与本地三件套一致，确认才运行：

~~~powershell
& $gh release edit "v$v" --repo $repo --draft=false --latest
& $py scripts/verify_release_routes.py $v $dir
~~~

国内加速 URL 为 https://gh-proxy.org/ 加上完整的 GitHub 公开附件地址。两条线路都须实际下载并通过签名/摘要校验；代理暂未同步时单独报告，稍后复查，不把失败写成成功。公开附件不可就地替换，修复时递增版本。固定百度网盘入口与提取码保留在设置和更新弹窗；发 GitHub Release 不会同步网盘文件。

## 安装与恢复

在可写目录运行便携版。软件内下载先在 .utatomo-update-*/next 重建完整目录，不改原程序。补丁只包含变更文件，未变化的运行库尽量使用同卷硬链接；本机基线不匹配时先询问，再下载完整包。不同意或下载失败仍可使用旧版。

点「重启并更新」后，助手等咏伴退出才替换 Utatomo.exe、_internal、docs、THIRD-PARTY-LICENSES 和随包说明。个人 data、缓存和根目录其他文件不参与切换。新版界面初始化写入 started；提前退出则恢复旧文件。新版正常使用后，可退出咏伴删除本次的 .utatomo-update-* 目录，释放旧版备份空间。

如果断电或更新报错，先退出该安装目录的咏伴，查看任务目录内的 update-error.txt。保留原目录，最简单的恢复方式是把正式完整包解压到空目录，再复制旧 data。不要把部分切换后的 _internal 混入新包，也不要删除旧曲库。
